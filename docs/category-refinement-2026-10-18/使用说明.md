# 分类细化程序

先看 `分类细化报告.md`，完整移动路径和来源文件状态保存在 `分类计划.json`。

- `执行分类.py`：执行固定 JSON，不联网、不调用模型、不重新分类。默认只读预演。
- `生成报告.py`：最初的分类判断与报告生成逻辑。日后人工改 JSON 后不要直接运行它，以免覆盖调整。
- `test_executor.py`：临时目录测试，写入范围仅限自动创建的临时目录。

修改某项去向时，编辑 JSON 中对应 ID 的 `proposed_path` 和 `reason`；要暂缓，则设置 `status` 为 `review`、`proposed_path` 为 `null`。保留 ID、原路径、文件清单和扫描时间。目标名称必须保留来源文件或目录名，目标类别限已商定的十类。

从修改后的 JSON 更新报告和执行摘要：

```bash
python3 "docs/category-refinement-2026-10-18/执行分类.py" --report
```

预演：

```bash
python3 "docs/category-refinement-2026-10-18/执行分类.py"
```

实际执行命令位于报告末尾，摘要必须与当前 JSON 完全匹配。审核报告后再执行。未来执行环境需要有 `/Volumes/分类` 的写入权限。

程序会先检查整批计划，再逐项移动：同卷 `/bin/mv -n`、不覆盖、原名保留、影片目录整体移动、源目标读回。出现异常立即停止；本地 `执行日志.jsonl` 保留已开始和已完成的记录。保留同一 JSON 和日志重跑即可恢复；不能仅凭目标存在就认定执行过。

执行全部成功后生成 `执行结果.json`。待讨论条目原地保留，原分类目录不删除。本地旧命名扫描 tracker 未在此次修改；以后使用它继续命名整理前，需要重新与实时 NAS 路径核对。

源文件核验为目录清单、文件大小、修改时间，没有对全部视频做内容哈希；同卷移动不转码、不重封装。

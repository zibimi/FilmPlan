# 电影分类规则

这是用户的收藏规则，不是通用电影类型标准。规则版本：2026-10-27-v2。

英文版：[SKILL.en.md](SKILL.en.md)（同一 skill 的英文入口，目录名保持中文）。

## 每次运行

1. 读取 [references/rules.md](references/rules.md)，按当前请求选择源目录。未指定源时询问范围；不要自行扫描整库。用户明确说“要分类”时，默认 `/Volumes/分类/合集/要分类`。
2. 用 `scripts/inventory.py` 获取当前目录、文件和资源关系线索；它只读 NAS，输出写本地工作区。挂载丢失、读取失败都不能当作空目录。旧计划只作线索，必须核对当前文件。
3. 按 [references/workflow.md](references/workflow.md) 核实电影身份、研究主体叙事、给出归属和理由。不要把资料缺口交给用户；用户只决定收藏偏好。名字尚未规范但身份可确定时可以研究归类；改名与移动分开列计划。
4. 默认输出可审阅的 Markdown 报告和固定 JSON 计划，保留原路径、来源、规则状态、资源组、备选项、理由、稳定 ID。拟执行时另生成只消费该计划的确定性代码，执行阶段不得重新推断类型。
5. 只有当前请求或本会话已有授权覆盖具体动作时才执行。建立 skill、认同规则、同意研究不等于永久允许整理全库。已经明确批准的具体条目不要反复索要确认；核对文件变化和授权范围即可。
6. 运行结束分别报告已研究、待核实、待偏好决策、计划移动和实际执行数量。分类偏好不明确的保留原处；身份明确且没有主导类型的可归故事，不能以故事掩盖认错电影。

本会话“要分类”的持续授权：身份明确、归类置信度达到约 80% 时，可生成固定计划并通过检查后直接移动，无须逐片再次确认。80% 是有依据的判断，不是统计概率；低把握、身份不明、同名冲突和暂停系列保留。此授权不扩展到整库、删除、去重或其他动作；建议规则的高信心应用不等于把该规则升级为已确认偏好。

## 规则与范围

- 用户最新指令优先，其次本 skill 的已确认规则，再次本 skill 的建议规则。建议规则可以生成候选，不视为用户已批准移动。
- 本 skill **取代**旧 `nas-film-curator/references/category-routing.md` 中“类型标签一致就直接归类”“华语片自动路由”“必须先完成改名才可研究分类”的冲突规则。可借用其 NAS 安全能力，但不能重新引入旧分类逻辑。
- 当前默认不向“华语世界”归档，不处理系列归并；合集可作为明确指定的源目录。“系列先不用管”不是把系列拆成单片的授权。
- 不扫描 `#recycle`、隐藏项、`/Volumes/分类/华语世界/禁`、`/Volumes/分类/合集/蚂蚁`，除非用户明确重开该范围。不要跟随符号链接。
- 此 skill 不顺带去重、删文件、转码、改名、同步全库跟踪器、整理导演库或发布 GitHub。另有明确任务时再做。
- 字幕、花絮、分段和同片版本保持关联；跨类冲突不靠复制多份解决。

## 调用示例

- `$film-category-rules 审阅 /Volumes/分类/故事，先给预览。`
- `$film-category-rules 整理要分类，排除华语世界，不处理系列，生成分类报告和固定计划。`
- `$film-category-rules 按我批准的计划执行其中指定的条目，完成后核验。`

本 skill 是可反复调用的工作流程，不是后台任务；“一直用”不创建自动定时运行。
